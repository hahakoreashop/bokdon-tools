> 클라우드 루틴이 매 실행마다 **이 파일을 읽고 그대로 따른다.** 프롬프트는 짧게 두고, 규칙·품질기준은 전부 여기서 관리한다(수정도 이 파일만 고치면 됨).
> 짝 파일: `templates/template-inline.html` (발행용 HTML 골격 — ★반드시 이 골격을 따를 것)

## 0. 절대 규칙 (어기면 사고)
1. **1회 실행 = 최대 1건 발행.** 여러 건 금지(구글 Scaled Content Abuse·애드센스 위험).
2. **스타일시트 블록 태그 금지 — 인라인 `style="..."` 속성만 사용.**
   - 창구(토큰) 경로엔 로그인 사용자가 없어 WordPress kses가 스타일시트 블록을 **통째로 제거**한다 → CSS가 본문에 **텍스트로 쏟아진다**(2026-07-26 글 206 실제 사고).
   - kses는 `style="..."` 속성은 허용하므로 **모든 스타일을 인라인 속성으로** 넣는다.
   - kses가 `display:flex`·`gap` 등을 지울 수 있어 **다단 배치는 `<table>`로** 한다. 그라디언트 대신 **단색 네이비**.
   - `::before`, `@media`, `:nth-child` 사용 불가 → 체크표시는 `✓` 문자를 직접 쓴다.
3. **`<h1>` 금지**(WP 제목이 h1). 본문은 `<h2>`부터.
4. **중복 발행 절대 금지.** 아래 2단계 이중확인 필수.
5. **검수 게이트 통과 없이 발행 금지.** 판정 우회 금지.
6. **토큰 값을 로그·보고·커밋에 남기지 마라.**
7. 저장소를 수정·커밋·PR 하지 마라. 작업은 발행과 보고까지.

## 1. 페이싱
- `queue.json`의 `count` 확인 → `count>=10`이면 하루 목표 2건, 아니면 1건.
- `GET /bokdon/v1/posted?token=…` → `todayCount`가 목표 이상이면 **아무것도 하지 말고** `스킵: 오늘 몫 완료` 보고 후 종료.

## 2. 후보 1건 선택 (중복 이중확인)
- 후보 순서: `queue.items`(조회수순) → 비었으면 `popular.items`(조회수순).
- **(a) 창구 posted**: 후보 `id`가 `posted` 배열에 있으면 skip.
- **(b) 실시간 사이트 대조(필수)**: `GET https://bokdon.com/wp-json/wp/v2/posts?per_page=100&_fields=id,slug,title` → 후보와 **같은 제도/주제**가 이미 있으면 skip.
  - ※기존 글 다수가 손으로 발행돼 `posted`에 없다. 이미 있는 주제 예: 국민내일배움카드, 근로·자녀장려금, 국민취업지원제도, 전세보증금반환보증, 기초연금, 청년도약계좌, 국민연금 예상수령액, ISA, 연금저축·IRP, 내집마련 디딤돌대출, 구직급여(실업급여).
- 둘 다 통과한 **첫 후보** 선택. 모두 걸리면 `스킵: 새 후보 없음` 보고 후 종료.

## 3. 사실 검증 (YMYL 1차)
- 후보 제목으로 **WebSearch** → 2026년 기준 **금액·자격·신청방법·기한**을 확인하고 **수치와 출처를 메모**(검수자에게 넘길 근거).
- 서로 다른 출처가 엇갈리면 **단정하지 말고** "출처에 따라 다름/공식 확인 필요"로 처리하거나 그 수치를 뺀다.
- ①제목·소관기관 ②지원대상/내용/신청방법 중 2개 이상 ③검증 가능한 최신 정보 — 못 채우면 다음 후보로.

## 4. 글 작성 (프리미엄 품질 — 여기서 대충하면 안 됨)
- **골격은 `templates/template-inline.html`를 그대로 가져와** 내용만 채운다(주석은 제거). 색·여백·구조를 임의로 바꾸지 말 것.
- **필수 구성 요소(하나라도 빠지면 검수 반려 대상):**
  1. 태그칩 + 히어로(단색 네이비, **핵심 숫자 3개** 테이블)
  2. **30초 요약** 4줄 이상
  3. 리드 문단 + 최종정리 날짜 줄
  4. "이 글은 이런 분에게" 4줄 이상
  5. 목차(섹션 수와 일치)
  6. **넘버 H2 섹션 6개 이상** — 각 섹션에 실질 정보. 표·단계·콜아웃을 섞을 것
  7. **표 3개 이상**(자격 요건 / 금액·한도 / 기간·일수 등)
  8. **예시 계산 박스 1개 이상**(실제 숫자로 "이런 경우 얼마")
  9. **체크리스트**(✓ 문자, 5줄 이상)
  10. **FAQ 6개 이상** — 실제로 궁금해할 질문, 답변은 2문장 이상
  11. **CTA 버튼 2개 — ★위치를 매번 랜덤으로(고정 금지)**
      - **CTA1 🧭 진단기 버튼** → **넘버 H2 1~4번 섹션 중 하나를 무작위로 골라 그 섹션 끝**(= 다음 H2 바로 앞)에 넣는다.
      - **CTA2 🏛️ 공식 신청 버튼(초록)** → **넘버 H2 6~8번 섹션 중 하나를 무작위로 골라 그 섹션 끝**에 넣는다. **반드시 「자주 묻는 질문」(FAQ) H2 *앞*** 이어야 한다. (섹션이 8개 미만이면 FAQ 직전 섹션 끝에 넣는다.)
      - ★**매 글마다 위치를 다르게 하라.** 예: 이번 글이 2번·7번이면 다음 글은 4번·6번처럼. **항상 같은 자리면 자동생성 티가 나서(봇처럼 보여) 구글·독자 신뢰도에 나쁘다.**
      - 두 버튼은 **최소 2개 섹션 이상 떨어뜨린다**(붙여놓기 금지). 사이가 벌어져야 클릭률이 살고, 나중에 각 버튼 주변에 광고를 배치할 공간도 생긴다.
      - **버튼 크기**: `font-size:20px; padding:22px 24px; border-radius:16px` 유지 — 모바일에서 손가락으로 편히 눌리는 크기(어르신 독자). 임의로 줄이지 말 것.
      - 참고: 템플릿(`template-inline.html`)에 있는 CTA 위치는 **예시일 뿐**이다. 실제 글에선 위 규칙대로 **직접 옮겨서** 배치하라.
      + 공식 확인 박스(초록, 출처 안내)
  12. 내부링크(`/finder/` `/diagnosis/` `/jiwongeum/`)
  13. **강한 면책**(템플릿 문구 그대로 + 주제 맞춤 보완)
- **분량**: 태그를 뺀 실제 본문 텍스트 **6,000자 이상**(HTML 포함 길이가 아니라 읽는 글자 수 기준).
- **톤**: 어르신·시니어도 읽기 쉬운 쉬운 말. 문단은 짧게. 전문용어는 한 번 풀어 설명.
- **YMYL 필수**: "복돈은 정부 공식 아닌 민간 정리 사이트" 고지, "참고·최대치" 표현, 확정·보장 단정 금지, 투자·종목 권유 금지, 공식 출처 링크.

## 5. ★발행 전 자체 점검 (실패하면 고쳐서 재점검)
아래를 **직접 문자열 검사**로 확인한다. 하나라도 걸리면 발행하지 말고 수정:
- [ ] 본문에 스타일시트 블록 태그가 **0개** (`<` + `style>` 형태 검색)
- [ ] `style="` 속성이 **40개 이상**
- [ ] 본문에 CSS 코드가 텍스트로 노출되지 않음 — `{`와 `}`가 붙은 CSS 패턴(예: `px;margin:`)이 태그 밖에 없어야 함
- [ ] `<h1` 없음
- [ ] `<h2` 6개 이상, `<table` 3개 이상, FAQ 블록 6개 이상
- [ ] 면책 문구·공식 링크 포함
- [ ] 실제 본문 텍스트 6,000자 이상

## 6. ★검수 게이트 (생략·우회 금지)
Task 도구로 **서브에이전트**를 띄워 심사시킨다. 검수자는 **반박하는 입장**이며, 애매하면 통과시키지 않는다.
- 넘길 것: 초안 HTML, 지원금 메타(제목·subsidy_id·공식링크), 작성자 근거(3번 수치·출처), 기존 발행글 목록(2번).
- 검수 7항목: ①사실 정확성(의심되면 **직접 WebSearch 재확인**) ②최신성(2026, 폐지·개정 여부) ③중복 ④YMYL(면책·민간고지·단정표현 없음·공식링크) ⑤**렌더 안전성(스타일시트 블록 없음·인라인 스타일 충분·CSS 텍스트 노출 없음)** ⑥품질·구조(위 4번 필수 구성요소 13개 충족·분량) ⑦정책(과장·낚시·얇은 글).
- 판정 JSON: `{"verdict":"PASS|REVISE|REJECT","score":0-100,"dup":bool,"issues":[{"항목","심각도","문제","수정지시"}],"요약":""}`
- **판정 처리:**
  - **PASS** → 발행.
  - **REVISE** → 수정지시대로 고친 뒤 **재검수**. PASS면 발행. (수정은 **최대 2회**까지 반복 가능 — 그래도 PASS 못 받으면 발행 말고 종료·보고.)
  - **REJECT** → 발행 금지·사유 보고.
- ★**검수자에게 반드시 알릴 것(호출 프롬프트에 포함):** *"고치면 살릴 수 있는 문제(수치 오류·표현·구조·분량·누락)는 **REVISE**로 판정하고 **정확한 값·수정지시를 구체적으로** 적어라. **REJECT는 고쳐도 답이 없을 때만**: ①이미 발행된 주제(중복) ②폐지·종료된 제도 ③신뢰할 출처가 없어 사실 확인 자체가 불가 ④정책 위반 소지."*
  - 이유: 숫자 하나 틀렸다고 통째로 버리면 그 회차가 헛돈다(2026-07-27 버팀목전세 신혼부부 소득기준 6천만원→실제 7,500만원 오류로 REJECT되어 0건 발행). **검수자가 정답을 알고 있으면 고쳐서 내보내는 것이 맞다.**
- ★**수정 후에는 반드시 재검수를 거쳐라.** 고쳤다고 바로 발행하지 말 것(수정이 또 다른 오류를 만들 수 있음).

## 7. 발행 (창구)
```
POST https://bokdon.com/wp-json/bokdon/v1/publish   (Content-Type: application/json)
{"token":"<TOKEN>","title":"...","slug":"...","content":"<div style=...>...</div>",
 "category_id":10,"subsidy_id":"<id>","tags":["이미지대기"]}
```
### 7-1. ★대표이미지(브랜드 썸네일) — 발행 전에 만들어 함께 보낸다
- 생성기: `.claude/skills/지원금-자동포스팅/make_thumbnail.py` (한글 폰트를 시스템→저장소 `assets/font-ko.ttf` 순서로 자동 탐색)
```bash
python3 .claude/skills/지원금-자동포스팅/make_thumbnail.py /tmp/cover.png "<분야태그>" "<지원금 짧은제목>" "<한줄 부제(핵심 숫자)>"
python3 -c "import base64;print(base64.b64encode(open('/tmp/cover.png','rb').read()).decode())"
```
  - 태그 예: `주거·자립 · 공공임대` / 제목 예: `2026 장기전세주택 완전정리` / 부제 예: `최장 20년 · 시세 80%`
  - 성공하면 그 base64를 `cover_b64` 로 함께 전송하고 **`tags`는 생략**(이미지가 이미 있으므로).
  - **실패(Pillow 없음·폰트 없음·에러)해도 절대 중단하지 마라.** 그 경우에만 `cover_b64` 없이 발행하고 `tags:["이미지대기"]`를 붙여 나중에 로컬에서 이미지를 보완하게 한다.
  - 보고 3줄째에 `썸네일: 생성(N bytes)/생략(사유)` 를 덧붙여라.
- 한글은 UTF-8 유지(`python json.dumps(ensure_ascii=False)` 권장).
- 응답: `{ok:true,id,link}` / `{skipped:"already_posted"}` / 400=본문이 너무 짧음.

## 8. ★발행 후 렌더 검증 (필수)
1. `GET https://bokdon.com/wp-json/wp/v2/posts/<id>?_fields=content` 로 **저장된 본문**을 받아:
   - `style="` 개수가 40개 이상인지 (인라인이 살아남았는지)
   - 스타일시트 블록 태그가 0개인지
   - CSS가 텍스트로 노출되지 않았는지
2. `GET <link>` 로 실제 페이지가 200인지, 제목·표가 보이는지.
3. **문제가 있으면 즉시 보고**하고(글 번호 포함), 다음 후보로 넘어가지 말 것.

## 9. 보고 (한국어 한 줄)
`발행: <제목> <link>` / `스킵: <사유>` / `검수반려(REJECT): <사유>` / `실패: <에러>` 중 하나.
- 검수에서 수정을 거쳤으면 결과 줄 끝에 `(검수 REVISE N회 후 통과: <무엇을 고쳤는지 한 줄>)` 를 덧붙여라.
토큰 값은 절대 포함하지 마라.
